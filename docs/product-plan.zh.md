# 平替穿搭助手：产品和架构方案（v1 草稿）

> 2026-10-04。截止时间：10 月 6 日（周二）。这份是待确认的方案，确认后再开始写代码。

## 1. 一句话定位
**把社交媒体上的“种草”变成适合你的平价穿搭。** 用户上传一张穿搭图，系统识别出每件单品，结合用户的身形、风格档案和当下流行趋势，从平价商品库里找相似款，并解释“为什么适合你”。

## 2. 和淘宝拍立淘、SHEIN 拍照搜索有什么不同
这两个功能都已经存在，SHEIN 自己就有 [Camera Search](https://www.facebook.com/SHEINUS/videos/introducing-camera-search-a-new-way-to-shop-at-shein/965374890608350/)。它们回答的是：**这张图里的东西，我们店里有没有长得一样的？**

我们回答的是：**我喜欢这套穿搭，用我的预算、我的身材、我的风格，怎么穿出来？**

| | 拍照搜同款 | 我们 |
|---|---|---|
| 目标 | 找一模一样的 | 找平替，并说明为什么适合你 |
| 是否了解用户 | 不了解，每次搜索都是独立的 | 有风格档案和身形档案，会越用越懂你 |
| 结果 | 一张商品列表 | 按单品拆开，给出原价和平替价的对比，还有搭配建议 |
| 趋势 | 没有 | 告诉你这套穿搭属于哪种流行风格，比如“老钱风” |

## 3. 功能（按优先级）
| 优先级 | 功能 | 说明 |
|---|---|---|
| P0 | 个人档案 | 第一次进入时填写身高、体重、年龄、身形（用户自己选）、偏好风格、预算 |
| P0 | 图片找平替 | 上传图片后，AI 拆出单品和属性，每件单品给出 3 到 5 个平替，每个都附上“为什么推荐”的说明 |
| P1 | 风格档案（记忆） | 每次上传和收藏都会被记下来。系统统计你常出现的颜色、版型和风格标签，AI 生成一段“你的风格”总结，之后推荐时据此排序 |
| P1 | 流行趋势 | 定时任务（比如每周一次）整理当季流行的风格，分成几类（老钱风、千金风、裸装风等），每类给出热门关键词、描述，以及商品库里的代表款 |
| P2 | 身形建议 | 根据身高、体重和身形，给出版型建议。上传照片分析放到以后再做，因为涉及隐私 |
| P2 | 部署上线 | 先在本地跑，之后再决定是否买域名部署 |

### 关于趋势数据的现实情况
小红书、TikTok 和 Instagram **都没有开放的公开 API**，抓取它们违反用户协议，而且有很强的反爬机制。两天内也做不稳。所以方案是：
- 定时任务调用 Claude 的**联网搜索**，汇总公开的时尚文章和趋势报道，再生成结构化的趋势分类。
- 可选接入 **YouTube 官方 API**（合规，需要申请 Key），统计穿搭视频的热门关键词。
- 自带一份种子数据：没有 Key 或者网络失败时用它兜底，保证评审也能看到趋势页。

面试时把这一点讲成一个**主动做的取舍**（合规和可靠性优先），反而是加分项。

## 4. 架构
```
浏览器（React 网站）
     │
 ┌───▼───────────┐   限流、上传大小限制、路由、请求 ID
 │  API 网关      │   （Nginx）
 └───┬───────────┘
     │
 ┌───▼───────────┐   档案 / 平替搜索 / 风格档案 / 趋势 API
 │  API 服务      │   （Python FastAPI）
 └───┬─────┬─────┘
     │     │ 把任务放进队列
     │  ┌──▼──────────┐   图片识别（Claude 视觉）
     │  │  Worker     │   定时趋势任务、风格档案更新
     │  └──┬──────────┘
 ┌───▼─────▼───┐  ┌────────┐  ┌──────────────┐
 │ Postgres +  │  │ Redis  │  │ Claude API   │
 │ pgvector    │  │ 队列/缓存│  │ （无 Key 时用 │
 │ 商品向量     │  │ /限流   │  │  模拟实现）   │
 └─────────────┘  └────────┘  └──────────────┘
          监控：Prometheus + Grafana（时间不够就只保留 /metrics）
```

**关键设计决定（面试可讲）：**
- **图片识别走异步队列：** LLM 识图要几秒，不能卡住网关。上传后先返回任务 ID，前端轮询结果。可以讲超时、重试和幂等。
- **先把图片转成文字，再做语义搜索：** 不用自己训练识图模型。商品库用 H&M 公开数据集里已经算好的向量（BGE-small，CC BY 4.0），查询时用同一个模型在本地生成向量。
- **排序 = 相似度 + 价格 + 风格匹配 + 身形规则：** 每一项都可解释，也可以单独测试。
- **风格档案 = 结构化统计 + LLM 总结：** 统计部分可测试，总结部分只负责“说人话”。
- **LLM 可替换：** 测试、CI 和没有 Key 的情况都用模拟实现，保证换台机器也能跑。
- **网关用 Nginx，不自己写：** 两天内把时间留给业务。限流、上传大小限制等规则写在配置里。

## 5. 测试和验证
- **单元测试：** 排序打分、风格档案统计、LLM 输出解析（包括 AI 返回格式错误的情况）。
- **集成测试：** 用模拟 LLM 跑完整流程：建档 → 上传 → 拿到平替。
- **AI 效果评估：** 准备约 20 张带标注的穿搭图，检查单品识别的召回率和平替的品类命中率，用 `make eval` 出报告。这一项直接回答 PDF 里的“how you validate AI output”。
- **CI：** GitHub Actions 每次提交都跑测试。

## 6. 自动化（PDF 看重 DevOps/SRE）
- `make up`：一条命令启动全部服务，并自动导入商品数据。
- `make test` / `make eval`：跑测试和 AI 评估。
- 定时趋势任务带重试、失败兜底和运行记录。
- 健康检查和 `/metrics` 接口。
